# 代码组织与依赖规则

## 后端

- `cmd/leafwiki` 解析命令行和运行配置，管理服务生命周期。
- `internal/core` 保存业务规则、业务服务和数据访问。核心层不引用 Gin、HTTP 层或应用组装层。
- `internal/core/shared` 按随机值、文件写入、解压限制、数据库和错误类型集中维护基础能力。
- `internal/wiki` 组装服务及按业务划分的请求处理。各业务模块通过核心服务合作，页面变更共同使用 `pagesave`。
- `internal/http` 提供路由基础设施、中间件、传输结构、统一错误响应和前端资源服务。
- `internal/testutil` 保存测试夹具和断言辅助能力。单元测试位于被测模块旁边。

## 前端

- `ui/src/app` 负责启动、路由、布局和业务组件注册。
- `ui/src/features` 按功能组织界面、状态和专用处理逻辑。
- `ui/src/shared` 保存基础组件、通用工具、接口契约、国际化及跨功能状态，不引用功能层和应用层。
- 请求客户端使用显式配置接口读取认证模式。会话状态仅处理状态，认证流程协调网络请求和状态更新。
- 注册器实例与标识位于公共层，组件绑定位于应用层。设置导航元数据与设置页面组件分别维护。
- 角色和页面类型位于 `shared/contracts`，接口客户端和状态共同引用。
- `ui/feature-interfaces.json` 声明允许跨功能调用的模块入口。检查脚本同时验证入口约束、公共层依赖和运行时循环依赖，应用组装层负责直接绑定界面组件。
- 快捷键按注册对象清理，只触发当前界面模式中最后一个符合条件的动作。

## 构建与验证

- 前端工程入口为 `ui/package.json`。
- Windows 启动入口为 `scripts/start.ps1`，使用系统工具路径、可信证书和后台进程状态文件。`BasePath` 参数与 `LEAFWIKI_BASE_PATH` 同时用于后端路由、就绪检查和访问地址，网关及管理端口自动选择空闲端口。
- 浏览器测试位于 `tests/e2e`，代理认证测试位于 `tests/proxy`。测试工具依赖与应用 Go 模块隔离。
- `go test ./...` 检查后端行为和依赖边界，`go vet ./...` 执行静态检查。
- 在 `ui` 执行测试、类型检查、格式检查、ESLint、生产构建和 `npm run check:architecture`。
- 浏览器测试支持通过 `E2E_BROWSER_CHANNEL` 使用本机已安装的浏览器，通过 `E2E_BASE_URL` 指向隔离实例。

## 数据与维护

运行数据、构建产物、测试报告和依赖目录由忽略规则排除。管理员密码恢复使用认证服务的密码处理，指定密码通过环境变量传入，不写入源码和日志。恢复时保留账号 ID，并撤销该账号旧会话。
