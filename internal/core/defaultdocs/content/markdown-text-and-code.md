# 文本格式与代码表达

文字格式用于让读者辨认重点、参数和引用的原文。它不能替代内容结构。把整段文字都加粗，读者就无法知道真正需要注意哪一句。把普通说明全部放进代码块，会丢失正常换行和链接行为。本篇围绕文字强调、代码示例和公式给出明确写法。

阅读前可参考[入门与写作流程](/markdown-getting-started)，涉及较长步骤时配合[列表与内容组织](/markdown-lists-and-structure)。所有示例以 LeafDoc 当前预览为准，扩展写法不要直接当作所有 Markdown 编辑器的共同能力。

## 粗体、斜体和组合强调

一对星号表示斜体，两对星号表示粗体，三对星号表示粗斜体。标记必须成对，并且紧贴需要强调的内容。中文、英文和数字可以放在同一对标记内。标记内部两端多出的空格会改变解析结果，不要用空格把星号与文字隔开。

```markdown
这是 *斜体文字*。
这是 **关键步骤**。
这是 ***需要突出的一句话***。
```

实际效果：这是 *斜体文字*，这是 **关键步骤**，这是 ***需要突出的一句话***。斜体适合术语与轻度强调，粗体适合必须先看到的条件。粗斜体使用次数应少于粗体。文字很短时强调效果清楚，整页都使用强调会增加阅读负担。

下划线也能参与强调，但词中下划线、相邻标点和中文组合会使规则更难记。教程和日常写作优先使用星号。变量名、文件名或带下划线的标识写成行内代码，不必依赖反复转义。遇到强调没有生效，先把内容简化为两侧完整的星号，再检查附近标点和空格。

## 删除线表达作废信息

LeafDoc 使用 GFM 扩展支持删除线，两侧各写两个波浪号。删除线表示这段内容仍供读者理解，但不再作为当前要求。正式操作文档不应长期堆放旧规则，清晰的当前说明比大量删除线更容易执行。

```markdown
~~旧附件不再使用~~，请打开当前页面的附件。
```

实际效果：~~旧附件不再使用~~，请打开当前页面的附件。删除线不等于数据库删除，也不会阻止搜索到这段文字。敏感内容不能仅靠删除线隐藏，应通过正确的数据管理流程移除。

## 行内代码保留原文

用一对反引号包围短代码，适合变量名、键名、文件扩展名、命令参数和少量原始语法。行内代码中的星号不会变成强调，HTML 标签不会按标签执行。不要把整句自然语言都标为代码，等宽字体适合精确字符，不适合长篇阅读。

```markdown
配置项是 `siteName`，文件扩展名是 `.md`。
输入 `**文字**` 可以生成粗体。
```

需要在行内代码里显示反引号本身时，用两条反引号作为边界。例如下面原文显示一个包含单条反引号的片段。边界条数要大于内容中连续反引号的条数，不能靠反斜线在代码内部解决所有情况。

```markdown
``这里包含 ` 符号``
```

行内代码会处理首尾空白，不适合讲解精确数量的缩进。需要说明空格、换行或多行配置时使用代码块，并在文字里写明空格数量，不要指望读者从屏幕上数不可见字符。

## 围栏代码块和语言标记

三条反引号单独成行打开代码块，另一组三条反引号单独成行结束。开始围栏后写语言名称，可以启用对应的语法高亮。语言名不代表代码会自动执行，浏览器只是展示原文。没有运行环境的示例应说明用途，不能把高亮颜色当作执行成功的证据。

```json
{
  "siteName": "LeafDoc",
  "enabled": true
}
```

上面是 JSON。属性名和字符串必须使用双引号，不能加尾随逗号，也不能加入 JSON 不支持的注释。需要解释字段时，把解释写到代码块外。配置可读性和可复制性同样重要，不能为了说明而让示例变成无效数据。

```powershell
$document = '使用说明.md'
Get-Item -LiteralPath $document
```

这段 PowerShell 展示按文件名读取项目信息的形式，文件是否存在由执行环境决定。命令示例要说明操作系统和当前目录。不要把提示符一起写进可复制命令，也不要把示例密码或本机私有地址误当成通用配置。

## 在代码块里讲解代码块

要展示含三条反引号的 Markdown 原文，外层使用四条反引号。外层围栏比内部围栏长，解析器才能把内部结束符当作内容。开始和结束围栏使用同类字符，关闭围栏的长度不能少于打开围栏。

````markdown
```text
这里是一段纯文本示例。
```
````

波浪号也可以作为围栏。团队选择一种常用写法即可，不必在同一文档随意混用。缩进式代码块需要行首四个空格，但在列表里会与嵌套结构相互影响，因此日常优先使用明确的围栏。代码块结束后留空行，再写普通正文。

## 上下标与数学公式

上下标不是所有 Markdown 都支持的原生语法。在 LeafDoc 中可以使用经过安全处理的 HTML 标签表达简短上下标，例如水写成 H<sub>2</sub>O，平方写成 x<sup>2</sup>。对应原文如下，不要把 `^2^` 或 `~2~` 当作已启用的通用扩展。

```html
H<sub>2</sub>O
x<sup>2</sup>
```

项目启用了数学公式扩展，并关闭单美元符号的行内公式解析。行内公式使用双美元符号，独立公式让双美元符号各自占一行。金额中的单美元符号保持普通文本，不要照搬其他编辑器的单美元示例。

```markdown
行内关系：$$a^2 + b^2 = c^2$$。

$$
\frac{a+b}{2}
$$
```

行内关系：$$a^2 + b^2 = c^2$$。

$$
\frac{a+b}{2}
$$

公式使用的是数学排版语法，不是任意程序代码。花括号负责组合表达式，反斜线引入数学命令。公式显示成原文时检查定界符，公式报错时缩减到一个最小表达式，再逐项恢复。不要为了展示某个不受支持的命令而关闭安全处理或忽略页面错误。

## 可复制示例的检查

代码示例应当保留必要缩进，避免智能引号、全角空格和不可见控制字符。解释文字放在代码块外，运行结果使用另一个 `text` 代码块，明确区分输入与输出。示例需要用户替换值时用直白说明，不能让占位符看上去就是可直接运行的真实参数。

颜色、字体和折行方式由页面样式决定，原文的语义不能依赖某一种颜色。深色主题下也应检查代码边界、对比度和横向滚动。小屏幕中长命令不要人为插入会改变语法的换行，应让代码区域自行滚动，或使用对应语言正式支持的续行写法。

本篇检查标准是每种格式都有正确边界，每段代码都有完整围栏，JSON 等示例符合对应语言规则，公式使用当前项目的双美元定界符。继续阅读[扩展语法与排错](/markdown-extensions-and-troubleshooting)，可以了解 HTML 清理和不同渲染器之间的差异。

示例涉及文件和网络时，明确哪些操作只读取数据，哪些操作会写入或删除内容。教程中的演示应当使用专门的测试对象，检查完成后清理临时文件，避免读者把真实业务资料作为练习对象。
