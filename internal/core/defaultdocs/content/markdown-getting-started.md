# Markdown 入门与写作流程

Markdown 用普通文本记录文档结构。标题前的井号、列表前的短横线、链接两侧的方括号都是正文的一部分。编辑器负责把这些标记转换成便于阅读的页面。你保存的是文字，浏览器显示的是排版结果。学习时同时观察编辑区和预览区，比只记符号更有效。

这套教程分为五篇。本文讲基本写作流程，后续依次讲解[文本格式与代码表达](/markdown-text-and-code)、[列表、引用与内容组织](/markdown-lists-and-structure)、[链接、图片与表格](/markdown-links-images-and-tables)以及[扩展语法、兼容性与排错](/markdown-extensions-and-troubleshooting)。按顺序阅读能够建立完整用法，也可以按问题直接查阅。

## 从一篇短文开始

在 LeafDoc 中登录后创建页面，填写能够说明内容的标题，再在编辑区输入正文。先写出结论和操作步骤，再添加格式。不要先排出复杂模板却留下空白内容。预览能正常显示以后保存，重新打开页面检查内容已经持久化。自动保存的实际状态以编辑器提示为准，关闭标签页前确认保存完成。

下面是一篇可以直接输入的短文。围栏中的内容是语法原文，复制时不需要把外层三条反引号一起复制。

```markdown
# 文件共享使用说明

本页说明团队成员如何上传和查找共享文件。

## 上传文件

1. 打开对应项目页面。
2. 进入编辑状态。
3. 上传附件并检查链接。

## 检查结果

保存后重新打开链接，确认文件可以下载。
```

显示结果中，文件共享使用说明是一级标题，上传文件和检查结果是二级标题，三项操作形成有序列表。段落之间的空行用于分开独立意思。即使读者看不到排版，这份原文也能够直接读懂，这是编写 Markdown 时值得保留的特点。

## 标题表达层级

一到六个井号分别表示一级到六级标题。井号后留一个普通空格，再写标题文字。页面标题与正文中的一级标题承担不同位置的显示职责，正文可以使用一个一级标题说明全文。不要为了字体大小随意跳级，例如一级后直接写四级会让目录结构难以理解。

```markdown
# 设备维护手册

## 每周检查

### 检查磁盘空间

#### 检查结果记录
```

标题要说明下面内容，而不是只写说明、其他、相关等缺乏信息的词。重复标题会生成不同锚点，引用时应复制实际显示的标题链接。LeafDoc 的目录面板和正文标题都从 Markdown 提取信息，正文使用三级以内的主要标题更便于浏览。四到六级仍能表示结构，但不应把所有句子都变成标题。

另一种标题写法是在文字下方添加等号或短横线，分别表示一、二级标题。短横线同时参与分割线和列表语法，初学时优先使用井号标题，减少歧义。井号出现在句子中间只是普通字符，只有满足行首标题规则才会产生标题。

## 段落、换行与空行

相邻文字行通常属于同一段落。你在编辑区按一次回车，并不等于浏览器一定显示一个可见换行。把句子拆成多行有利于原文维护，但要分成两个独立段落，必须在中间留空行。多个空行不会可靠地产生更大的视觉间距，不要用连续回车挤出空白版面。

```markdown
这两行文字
属于同一个段落。

这一行开始一个新段落。
```

确实要在同一段内换行，可以在行末添加两个普通空格后回车，或使用反斜线紧接换行。编辑器会让行末空格不易察觉，因此必须在预览中验证。不要把普通段落写成每行都强制换行，否则手机屏幕上会形成大量断裂的短句。

```markdown
收件人：文档管理员  
事项：更新操作步骤

值班时间：工作日\
联系渠道：站内账户信息
```

地址、署名、诗句适合强制换行，说明文字适合自然分段。HTML 的 `<br>` 也能表达换行，但纯 Markdown 写法更容易移植。这里的代码围栏会把尖括号原样显示，正文中是否执行 HTML 由渲染与安全规则共同决定。

## 普通文本中的特殊字符

井号、星号、方括号和反引号都参与语法。需要显示符号本身时，可以在符号前加反斜线，或者把一小段内容放进行内代码。转义只作用于特定标点，不是给任意文字加反斜线。Windows 路径适合写成行内代码，避免下划线和反斜线被误解。

```markdown
\# 这行显示井号，不生成标题
\*这里显示星号\*
文件位置是 `C:\资料\说明.md`。
```

全角符号和半角符号外观接近，语法含义却不同。标题使用半角 `#`，代码使用半角反引号，链接使用半角括号。中文输入法自动替换引号时，要检查示例里的引号是否仍然适合复制到程序。中文标点用于正文没有问题，不要将语法符号也替换为全角形式。

## 写作、检查与发布

把每一节当成读者需要完成的一件事。写操作说明时给出入口、输入内容、预期结果和失败后检查的位置。介绍概念时紧接一个示例，说明原文和显示结果的对应关系。长篇文档通过标题组织，不要把多个不相关主题挤进一段。

完成草稿后按读者顺序检查。标题能否让人快速定位，步骤是否缺少必要条件，示例是否能直接复制，链接是否指向真实页面，图片是否有说明。预览通过只代表排版成立，不代表操作正确。对于命令和配置示例，还应检查语法、环境要求与执行结果。

页面路径应保持稳定。标题调整以后，检查其他文档指向它的链接。不要把本机磁盘绝对路径当作可共享附件地址，另一台设备无法读取你的桌面文件。附件应通过项目提供的上传方式进入资源管理，再使用编辑器生成的地址。

## 常见问题定位

标题显示成普通文字时，检查井号后是否缺少空格，以及上一行是否打开了没有结束的代码围栏。正文整体变成代码时，检查行首四个空格或制表符，缩进在列表和代码语法中有实际含义。段落挤在一起时，在独立段落之间添加空行，而不是添加多个普通空格。

复制富文本后出现异常符号时，先使用纯文本粘贴，再逐段添加结构。保存后内容未更新时，查看保存提示、网络状态和当前页面路径，避免在另一个同名页面里检查。较长文档可以先完成小节再保存，确认稳定后继续，不要等到写完所有内容才第一次检查。

本篇完成标准是能够独立创建一篇包含三级标题、多个段落、一次显式换行和一个可用页面链接的说明文档。保留清晰原文与正确预览，再进入下一篇学习文字和代码格式。

日常维护时保留清楚的修改目的，核对相关页面是否需要同步更新。文档价值来自读者能够完成实际操作，格式只是帮助理解和查找的工具。
