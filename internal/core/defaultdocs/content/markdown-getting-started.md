# Markdown 入门与完整写作流程

Markdown 是一种用普通文字记录排版的写法。你输入井号表示标题，输入星号表示强调，编辑器把这些符号转换成可阅读的页面。文档既保留容易复制的原文，又能显示清楚的层级。开始学习时，不必一次记住全部语法，先完成一篇能够重新打开的短文，再逐步增加列表、链接和表格。

## 新建一篇有明确用途的文档

登录后使用页面创建入口，填写能说明用途的标题，例如“共享文件上传说明”。标题应回答这篇文章解决什么事。正文先写适用对象与完成目标，再写实际操作，避免只有一个标题和大量空白小节。页面地址由系统管理，跨页引用应复制实际页面地址，不能使用本机磁盘路径。

## 从原文到预览

在编辑区输入下面的内容，并在预览中观察标题、段落与列表。外层代码围栏只是为了展示原文，复制练习时只复制里面的内容。

```markdown
# 共享文件上传说明

本文用于说明如何提交项目附件。

## 上传步骤

1. 打开对应文档。
2. 进入编辑状态并上传附件。
3. 检查下载链接后保存。

## 完成标准

重新打开页面，确认文字完整，附件能够下载。
```

显示后，一级标题说明全文主题，二级标题把步骤与验收分开，数字列表表达操作顺序。源码中的空行让段落边界清楚。先保证内容能读懂，再选择需要强调的重点，不要为了让页面显得复杂而加入没有用途的格式。

## 段落与空行

两个段落之间留一行空行。连续两行文字会作为同一段落处理，编辑时换行不等于阅读时换段。用自然段表达独立意思，比在每一句后强制换行更稳定。中文段落不需要为了对齐而在开头输入多个空格。

```markdown
这是第一个段落，说明目标。

这是第二个段落，说明操作。
```

若同一段内必须换行，可在行末输入两个普通空格后回车，或使用反斜杠结尾。行末空格容易被编辑器清理，操作说明通常直接拆成列表更清楚。

## 标题层级

标题使用一至六个井号，井号后必须有空格。一级标题后通常接二级标题，二级标题下再使用三级标题。不要仅为了改变字体大小跳过层级，自动目录依靠标题结构组织内容。正文中的标题应尽量唯一，重复名称会让同页定位难以辨认。

```markdown
# 全文主题
## 操作步骤
### 上传前检查
### 保存后验证
## 常见问题
```

## 编辑、预览与保存

写完一段就检查一次预览，重点看列表有没有变成代码块、代码围栏有没有闭合、链接是否可点击。完成编辑后使用页面提供的保存入口，并等待保存状态明确完成。随后退出编辑并重新打开页面，确认内容是已经保存的版本，而不是仍停留在编辑区的草稿。

如果出现版本冲突，说明页面已被其他操作更新。保留自己未保存的文字，重新加载最新内容，合并后再保存。不要持续重复提交旧版本覆盖其他人的修改。

## 修改与历史版本

每次修改围绕一个明确目的，例如纠正一个步骤或增加一段说明。历史版本用于查看旧内容和恢复误改，不能代替保存。恢复前先查看目标版本的正文与资源，确认它对应需要的状态。恢复完成后重新打开页面，检查文本和附件，而不是只看到成功提示就结束。

## 一篇可以投入使用的文章

一篇操作文档至少说明适用对象、准备条件、具体步骤、成功现象和失败处理。用读者能实际观察的结果描述完成标准，例如“列表出现刚上传的文件，点击后能够下载”，比“确认一切正常”更容易执行。

```markdown
# 文档名称

适用对象：项目成员。

## 准备条件

说明需要的权限或文件。

## 执行步骤

1. 写明具体动作。
2. 写明保存位置。

## 检查结果

说明完成后会看到什么。

## 遇到问题

说明如何辨认问题，以及下一步操作。
```

## 常见错误与处理

标题没有变大时，检查井号后的空格。整段变成代码时，检查开头是否多了四个空格。保存后旧页面没有变化时，先查看保存状态，再确认当前打开的是同一篇文档。不要通过反复新建同名文章处理保存问题，这会制造多个内容不一致的入口。

## 核对语法来源

通用 Markdown 的规则可查阅 [CommonMark 规范](https://spec.commonmark.org/)。本系统还支持表格、任务清单等扩展，详细用法见后续文章。练习时以本系统的实际预览为准，其他网站支持的功能不能直接等同于当前页面支持的功能。
