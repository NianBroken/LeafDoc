# 链接、图片与表格

链接让文档连接到其他资料，图片展示文字难以说明的细节，表格帮助读者比较同类信息。这三种内容都依赖准确的地址和清晰的上下文。页面排版正常却打不开附件，仍然是一篇有问题的文档。本篇给出可以核对的写法，并说明 LeafDoc 内部页面与资源路径的区别。

相关内容包括[入门与写作流程](/markdown-getting-started)、[文本格式与代码表达](/markdown-text-and-code)及[扩展语法与排错](/markdown-extensions-and-troubleshooting)。这里的跨页链接使用页面标识，不引用本机桌面或下载目录。

## 行内链接与说明文字

方括号中写读者看到的文字，紧接的圆括号中写地址。链接文字应说明目标内容，不要在一页里反复使用这里、点击查看等无法区分的文字。地址中存在空格时使用正确的 URL 编码，不把文件系统路径直接粘到链接地址里。

```markdown
[阅读入门教程](/markdown-getting-started)
[CommonMark 规范](https://spec.commonmark.org/)
```

上面的内部链接指向本系统的入门页面，外部链接指向规范网站。外部资料会离开当前站点，应确保来源可信。文档管理员需要定期检查长期引用的地址，外部页面的标题和路径会变化，链接存在不代表内容永远保持一致。

链接可以带可选标题，写在地址后面的引号中。标题是辅助信息，不能替代链接文字，也不能把重要说明只放在鼠标悬停提示里，触屏设备没有同样的悬停方式。带有复杂括号的地址建议通过编辑器插入，并实际点击验证解析结果。

## 引用式链接减少重复

一页多次使用相同地址时，可以把地址定义集中放在页面末尾，用标识关联。标识只在当前 Markdown 文档中解析，不是全站变量。每个标识只保留一个定义，避免同名定义让维护者无法判断哪个地址生效。

```markdown
请先阅读[入门教程][intro]，再检查示例。
遇到格式问题时也可以返回[基础流程][intro]。

[intro]: /markdown-getting-started "Markdown 入门"
```

引用式链接特别适合较长外部地址，使正文原文更容易阅读。链接定义本身不会作为普通段落显示，标识没有定义时则会留下原始语法。检查时除了正文，也要检查末尾定义，不能只搜索完整 URL 出现的位置。

## 自动链接与邮件地址

用尖括号包围完整网址可以明确表示自动链接。GFM 还会识别部分裸网址，但为了减少句末标点被包含进地址的问题，正式文档优先使用明确的链接语法。邮箱链接可以使用 `mailto:`，它会调用读者设备上配置的邮件程序，不会由 LeafDoc 自动发送邮件。

```markdown
<https://spec.commonmark.org/>
[联系管理员](mailto:admin@localhost)
```

示例中的本机邮箱只是初始管理员身份信息，不是可投递的公共邮箱。文档中介绍真实联系方式时必须使用实际有效的地址。展示接口地址和命令参数时使用行内代码，避免读者误以为每一个字符串都应该点击。

## 标题锚点与页面路径

标题锚点由渲染器根据标题文字生成。空格、标点、重复标题和大小写会影响实际结果，不能完全照搬其他平台的生成规则。LeafDoc 为标题建立可导航的标识，最可靠的方法是从实际页面复制标题链接。修改标题后，再检查引用该小节的链接。

本页的[表格基本写法](#表格基本写法)使用当前中文标题作为锚点。完整跨页链接也能附加片段，例如目标页面地址后加井号和小节标识。浏览器会先打开页面，再定位标题，两个部分都必须有效。

内部文档链接使用页面路径，附件链接使用上传后生成的资源地址。页面重命名、移动和附件删除是不同操作，不能用改正文链接替代资源管理。启用子路径部署时，手写以斜线开头的站点根路径会绕过部署前缀，应优先使用项目解析支持的相对页面路径。

## 图片语法与替代文字

图片比普通链接多一个开头感叹号。方括号内是替代文字，用于图片不可见时说明内容，也帮助辅助阅读工具理解图像。替代文字应描述有用信息，例如上传按钮位于右上角，不要只写图片二字。图片附近还应写出读者需要观察的重点。

```markdown
![LeafDoc 默认标识](/defaults/leafdoc-logo.webp)
```

实际展示如下。地址由资源处理规则添加部署前缀，解析到项目内置资源，不需要访问原始下载文件。

![LeafDoc 默认标识](/defaults/leafdoc-logo.webp)

LeafDoc 支持在图片语法后紧接 `{width=40%}` 设置百分比宽度，例如 `![说明](/defaults/leafdoc-logo.webp){width=40%}`。比例必须大于零且不超过百分之百，标记写在图片后，不写在替代文字中。这是项目扩展，普通 Markdown 不保证支持。常规写作也可以使用自然尺寸和页面约束。确实需要固定宽度时，可以使用允许的 HTML 图片属性，并保留等比缩放。

```html
<img src="/defaults/leafdoc-logo.webp" alt="LeafDoc 默认标识" width="160">
```

不要同时填写错误比例的宽和高，图案会被拉伸。大图片应先合理缩小文件尺寸，不只是在页面上压缩显示宽度。透明背景要在深色和浅色主题中检查，截图里文字也要能看清。远程图片会依赖对方站点和网络，适合长期保存的资料应通过附件功能管理。

## 表格基本写法

表头下一行使用短横线建立分隔行，两侧竖线分隔单元格。表头和分隔行的列数一致，每个分隔单元格至少使用三个短横线。普通数据行保持相同列数，虽然部分渲染器会补齐缺失单元格，依赖自动补齐会让原文难以检查。

```markdown
| 内容 | 用途 | 检查方法 |
| --- | --- | --- |
| 链接 | 连接页面 | 点击打开 |
| 图片 | 展示图案 | 检查清晰度 |
| 表格 | 比较信息 | 核对行列 |
```

| 内容 | 用途 | 检查方法 |
| --- | --- | --- |
| 链接 | 连接页面 | 点击打开 |
| 图片 | 展示图案 | 检查清晰度 |
| 表格 | 比较信息 | 核对行列 |

表格适合字段固定、行与行可以直接比较的数据。长篇解释、完整操作步骤和大段代码更适合普通小节。把一整篇说明塞进两列表格，会让移动设备出现过度横向滚动，也让读者难以定位内容。

## 对齐和单元格内容

分隔行中的冒号控制对齐。左侧冒号表示左对齐，两侧冒号表示居中，右侧冒号表示右对齐。数字比较适合右对齐，名称和说明通常左对齐。这里的对齐控制单元格内容，不是让整张表格任意放置在页面中。

| 名称 | 状态 | 数量 |
| :--- | :---: | ---: |
| 入门文档 | 已完成 | 1 |
| 默认教程 | 已完成 | 5 |

单元格内可以使用强调、链接和行内代码。竖线本身要转义成 `\|`，包括需要在行内代码中显示竖线的情况，也应核对 GFM 对表格分隔的处理。不要在单元格中直接写多行围栏代码，普通 Markdown 表格不提供可靠的多段块结构。

合并单元格、跨行布局和复杂表头不属于普通 GFM 表格能力。优先拆成多张简单表格，或者链接到独立附件。确需使用 HTML 表格时，检查标签是否被安全规则保留，避免事件、任意样式或脚本。不能为实现复杂表格而降低整个站点的 HTML 安全限制。

## 资源与链接验收

保存后逐个点击内部链接，确认页面标题与预期一致。对图片检查请求状态、格式、透明度和尺寸。链接在预览正常而发布后失败时，核对当前页面路径、部署前缀和权限。图片只在本人电脑显示时，检查是否错误使用了本机文件地址。附件已经删除时，应删除正文引用或上传正确资源，而不是留下失效链接。

本篇完成标准是一页包含内部链接、引用式链接、实际图片、标题锚点和三列对齐表格的说明。所有目标都要通过真实点击或加载验证，原文看起来正确不能代替实际访问结果。
