# 列表、引用与内容组织

## 用列表表达动作

无序列表用于并列事项，有序列表用于必须按顺序执行的动作。每项只承担一个动作或一个判断。

```markdown
1. 打开系统入口。
2. 输入账号和密码。
3. 登录后打开文档树。

- 阅读记录
- 下载附件
- 检查链接
```

## 子列表与任务记录

子列表需要缩进，使它归属于上一项。修改缩进后查看预览，确认子项没有变成独立段落。

```markdown
- 检查系统
  - 打开首页
  - 查看搜索

- [x] 已核对访问入口
- [ ] 待补充备份位置
```

任务框用于文章中的状态表达。不能据此认定系统执行了对应工作，也不能把显示勾选等同于后台任务成功。

## 实际任务状态示例

- [x] 已确认页面保存成功
- [x] 已重新打开检查正文
- [ ] 尚未核对读者权限
- [ ] 尚未检查附件下载

> 每一项都应以实际检查结果为依据。

## 引用与分隔

```markdown
> 操作前应保留一份可恢复的数据副本。

---
```

引用适合突出一条独立说明，不能代替真实来源。分隔线用于切换大段内容，常规层次优先使用标题。避免每行都加分隔线，也不要把多种列表嵌套到读者无法判断先后关系的程度。

## 把清单写成可判断的结果

“检查部署”没有说明检查什么。写成“打开 HTTPS 首页，登录后读取一篇页面，确认内容完整”，读者才能判断工作是否完成。

## 为不同清单选择合适的结构

同一层列表应表达同一类信息。需要准备的资料放在一个无序列表里，必须先后执行的动作放在有序列表里，实际完成状态放在任务列表里。不要把准备条件、操作步骤和检查结果混成一串编号。读者在执行时应当能够从上往下逐项处理，不必回到上一段寻找缺失的输入或判断条件。每个列表项尽量只有一个主要动作，复杂解释移到它后面的短段落。

当一项工作包含多个分支时，先用正文写出选择依据，再分别列出对应操作。例如有管理员权限时打开设置入口，没有权限时联系负责人员授权。不要把互斥动作写成连续步骤，让读者误以为全部都要执行。子列表只表示归属，不自动表示优先级；重要程度需要在文字里明确说明。层级超过两层时，通常应拆成独立小节，使手机阅读和打印阅读都保持清楚。

## 将引用与事实来源对应

引用块可以突出一条需要注意的说明，也可以呈现他人的原话。引用实际资料时，应标明出处和适用条件，避免让读者把个人推断当作原文结论。只想提醒读者保存之前核对目标时，直接使用简短的提示即可，不必假借外部权威。提示不应代替操作步骤，也不应在每个段落前重复出现，否则真正关键的提醒反而难以辨认。

列表中的代码块、图片和补充段落需要缩进到所属项目下。预览时检查它们是否仍位于同一个项目内，尤其留意粘贴内容带入的制表符和多余空格。发现编号跳动时，先检查项目之间是否插入了未缩进的段落。分隔线适合区分大块独立主题，不适合代替每一级标题。组织结构的目标是帮助读者定位信息，而不是增加装饰。

## 按结果更新任务状态

任务框记录文章作者确认过的状态。勾选之前必须执行对应检查，并把检查对象与结果写清楚。一个登录页面能够打开，只能证明入口可达，不能证明账号登录、页面保存和附件下载都正常。将这些动作分开记录，接手人员才能知道下一步还需要做什么。任务失败时保留失败原因、出现的位置和下一次复查条件，不能只把勾选取消而删除全部线索。

维护清单时定期检查每一项是否仍然适用。已经取消的工作写明取消原因，需要转交的工作写明负责角色和交接资料的位置。避免把真实密码或其他私有内容写进任务条目。完成一轮检查后保存页面，再回到阅读界面核对项目顺序与状态。需要审查变更时使用修订记录查看正文变化，不能仅凭当前勾选状态判断过去发生的动作。
