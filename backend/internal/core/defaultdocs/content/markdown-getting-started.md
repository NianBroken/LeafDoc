# Markdown 入门与完整写作流程

## 从一篇实际记录开始

Markdown 是带有少量标记的普通文字。编辑区写下 `# 值班记录`，预览区便将它显示为一级标题。源文件仍然能用普通文本编辑器打开，标题标记不会变成只有某个办公软件才能读取的格式。

进入有编辑权限的账号后，创建页面并填写标题。在正文中写下下面的内容，查看预览，再保存。保存后返回页面，确认标题、列表和正文都存在。没有编辑权限的读者只能阅读，不能通过修改浏览器界面取得保存权限。

```markdown
# 值班记录

今天检查了文档服务。

- 首页能够打开
- 搜索能够找到记录
- 附件能够下载
```

## 区分页面标题与正文标题

页面标题用于导航，正文中的井号用于组织文章内容。修改其中一项后，应分别检查目录中的名称与正文呈现。给段落之间保留空行，让列表、代码块和正文边界清楚。

## 写作与核对

每次只完成一段有明确用途的内容。操作说明写清输入、动作和结果。例如写“打开搜索，输入值班，点击记录标题进入页面”，不要只写“支持搜索”。正文保存前核对链接目标，保存后重新进入页面确认结果。出现版本冲突时先读取服务器上的最新内容，再合并自己的文字，不能把旧页面当作最新版本直接覆盖。

内置教程来自程序嵌入资源。升级程序不等于把已有页面正文全部覆盖，已保存页面仍是实例自己的数据。

## 给记录确定用途和读者

写作前明确这篇记录要解决的具体问题。给新同事使用的说明，需要写出入口位置、所需权限和完成后的画面。给自己留存的值班记录，需要写出检查时间、检查对象和实际结果。不要把两类内容混在一起，让读者在大量背景文字中寻找下一步动作。标题尽量包含对象与动作，例如文档服务登录检查，比日常事项更容易被搜索到。

把真实内容填入示例后再保存。账号、密码、数据库连接资料和证书私钥不属于公开教程正文，不应为了演示完整而直接粘贴。需要说明配置的位置时写出字段用途，实际值由管理员在受保护的设置入口填写。文档面向多人阅读时，先确认页面权限，再判断内容是否适合分享，不能认为一个难猜的链接就等于访问控制。

## 完成一次可以复核的保存

一份可用的记录应同时包含检查条件、执行动作、可观察结果和后续处理。检查附件时，说明使用哪个账号、打开哪篇页面、选择哪个文件以及下载后如何确认内容。没有完成的动作写成待处理事项，不应使用已完成的语气。这样接手的人能继续工作，也能区分已经发生的事实与还未执行的计划。

编辑过程中定期保存，每次保存后观察成功提示。页面关闭前回到阅读界面，确认刚写入的一句独特文字仍然存在。遇到连接中断时保留自己的正文副本，恢复连接后读取服务器版本再决定如何合并。两个人同时编辑同一篇文章时，不要反复提交旧版本。版本冲突是在提示存在其他人的修改，应当逐段核对并保留双方仍然有效的内容。

## 练习与交付检查

创建一篇只供练习的记录，写一个正文标题、两段说明和三个检查项。预览时核对标题层次，保存后从文档树重新打开，再用搜索查找标题中的词。给记录加上一句新的结果，重新保存并检查修订记录。完成这套动作，才能确认自己理解了编辑、预览、保存、查找和修订之间的关系，而不只是把文字输入到页面里。

正式交付前请用读者账号再打开文章。确认图片能够显示、站内链接能够到达目标、附件能够读取，且正文没有留下个人设备路径。目录中的名称应当足以帮助读者辨认文章，正文开头应直接说明用途。后续维护时保留有效信息，删除已经证实过时的操作，并在正文中说明当前应当使用的入口。不要只改标题却保留旧步骤，否则读者仍会按过期内容操作。
