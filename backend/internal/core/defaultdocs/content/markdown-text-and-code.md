# 标题、文本格式与代码

本篇讲解文章中最常用的文字格式。格式的用途是帮助读者区分结构、重点和需要照抄的内容。普通说明保持普通文字，步骤中的按键、文件名或命令使用行内代码，长命令使用代码块。一个词同时叠加粗体、斜体和删除线会降低辨认速度，应根据用途选择最少的标记。

## 标题的完整写法

行首一到六个井号表示一到六级标题。井号后保留一个空格，标题结束后直接换行。标题前后留空行可以让源码更容易扫描。不要把整段解释写进标题，解释放在下一段。

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

同一篇教程通常只需要一个一级标题以及二、三级标题。自动目录读取这些层级。标题中包含代码、链接等格式时，检查目录中显示的文字是否仍然明确，避免把操作按钮或大段公式放在标题里。

## 粗体与斜体

两个星号包围文字表示粗体，一个星号表示斜体。标记与文字之间不留空格。中文重点通常采用粗体，斜体更适合书名、变量说明等辅助用途。

```markdown
普通说明，**必须保存的设置**，以及 *辅助说明*。
```

实际结果：普通说明，**必须保存的设置**，以及 *辅助说明*。

如果星号原样显示，检查两侧是否数量一致，标记内部的首尾是否夹有空格。不要跨越多个段落打开强调而不关闭，这会使后面的内容出现意外格式。

## 删除线

两个波浪号包围文字表示删除线。适合在说明中标明不再采用的文字，但长期文档应直接写清现行规则，避免让读者从大量划掉的段落里猜测当前操作。

```markdown
~~旧入口~~ 使用页面右上角的保存入口。
```

显示结果：~~旧入口~~ 使用页面右上角的保存入口。

## 行内代码

一对反引号包围短代码。它适合文件名、变量、命令片段和需要保持符号原样的内容。行内代码不会继续解释里面的星号与下划线。

```markdown
文件名为 `guide.md`，配置项为 `enabled`，标记原文是 `**重点**`。
```

显示结果：文件名为 `guide.md`，配置项为 `enabled`，标记原文是 `**重点**`。

如果内容本身包含一个反引号，用两个反引号作为外围边界，并在必要时加一格内侧空格。外围连续反引号的数量必须多于内容中的数量。不要把需要执行的多行命令塞进行内代码。

## 围栏代码块

三个反引号单独占一行打开代码块，结尾再用相同数量的反引号关闭。起始围栏后写语言名称，系统据此进行语法着色。语言名称影响高亮，不会执行代码。

````markdown
```json
{
  "title": "入门教程",
  "enabled": true
}
```
````

上面的内容显示为 JSON 代码块，双引号、缩进和换行会保留。复制代码前不要把语言标记或围栏一起复制进配置文件。中文字符串保存为 UTF-8，避免在不同编辑器之间出现乱码。

## 在文章中展示围栏

讲解 Markdown 时需要让三个反引号作为原文显示。外层使用四个反引号，内层使用三个即可。结束围栏应与它对应的开始围栏一致，不要用不够长的围栏提前关闭外层内容。

## 转义特殊字符

反斜杠放在标记字符前面，可以让它作为普通符号显示。需要展示多个复杂符号时，行内代码通常更容易阅读。

```markdown
\*这里不会变成斜体\*
\# 这里不是标题
\[这里不是链接\]
```

显示结果：\*这里不会变成斜体\*。示例中的井号被转义后不会形成标题。反斜杠不是用于随意修改网址的字符，Windows 路径应放在代码块中，不能直接作为网页链接使用。

## 空格、换行与字符

缩进四个空格的段落会形成代码块，因此正文不要用手工空格模拟段首缩进。全角空格与普通空格不是同一个字符，列表和代码语法需要普通空格。复制网页代码时还应检查引号是否变成弯引号，减号是否变成装饰性的长横线。

## 编辑检查清单

保存前检查所有代码围栏闭合，语言名称正确，命令中没有从说明文字带入的标点。需要用户修改的值在说明中逐项解释，并明确哪些内容必须原样保留。只对关键结论使用粗体，让正文保持稳定的阅读节奏。

更完整的基础规则见 [CommonMark 规范](https://spec.commonmark.org/)，删除线等扩展见 [GFM 规范](https://github.github.com/gfm/)。
