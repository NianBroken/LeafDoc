# Markdown 链接与扩展实践

## 把内容连起来

页面链接用于从当前说明进入详细步骤，图片用于展示界面，附件用于提供下载。引用目标必须真实存在，文字看起来像网址并不等于它能访问。

## 项目渲染能力

当前预览使用 Markdown 渲染、GFM 表格与任务列表、KaTeX 数学和 Mermaid 图表组件，并对 HTML 做清理。浏览器不会执行正文里的任意脚本。

## 操作建议

1. 先保存目标页面，再复制目标页面链接。
2. 在正文添加链接，保存后点击验证。
3. 移动或重命名页面后检查相关引用。
4. 使用页面提供的附件上传入口获取实际资源地址。

## 实践

阅读本章节的两篇子页面，建立一篇含链接、图片和流程图的练习文档。不要直接复制陌生机器上的绝对文件路径，读者浏览器无法读取作者本地硬盘。

## 链接是一条可执行路径

读者点击链接时，系统需要找到真实目标，不能只靠显示文字猜测。文档标题可以相同，路径和稳定标识用于区分。跨页面导航应在保存后亲自点击验证，不仅检查编辑器里括号是否闭合。移动页面后重新检查引用来源，避免旧地址留在其他页面。

## 图片承担说明任务

图片应有替代文字，周围正文解释它展示什么。不能只贴一张截图让用户猜点击哪里。截图里的主机名、密码和本地路径应避免作为通用操作参数。项目内置图片有稳定资源入口，用户上传图片使用服务器返回地址，不使用电脑文件路径。

## 扩展语法需要实际支持

Markdown 平台对扩展并不统一。本项目支持的数学和图表由前端组件决定，不能把其他编辑器的效果当成这里已经实现。遇到渲染不一致，用一段最小示例检查，再把复杂内容逐段加回，确认是哪项语法或资源导致差异。

## 安全清理是呈现约束

HTML 清理会移除不允许的标记和属性。不要通过脚本、事件处理属性或任意样式实现核心说明，内容应在允许的 Markdown 结构下仍清楚。文档页面不会成为执行任意 JavaScript 的入口。

## 完整练习

写一页操作路径，包含入门链接、一个真实图片和一幅三节点流程图。保存后从另一页面进入，逐个点击目标，确认前缀部署下仍能访问。检查手机宽度下的图片和代码块，再重新打开页面确认保存结果。

```markdown
## 实践记录

- 检查预览
- 保存后重新打开
```
