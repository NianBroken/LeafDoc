# 标题、段落与换行

## 标题

```markdown
# 项目使用说明
## 安装
### 检查结果
```

井号后必须有空格。一级标题用于文档主题，二级标题划分主要步骤，三级标题解释步骤内部内容。`#安装` 不会按标准标题解析。

## 段落与换行

```markdown
这是第一段，解释操作目的。

这是第二段，说明检查结果。
```

空行区分段落。普通单次回车不是可靠的强制换行方式，需要明确换行时在上一行末尾放两个空格后回车，或使用反斜线换行。

## 分隔线

```markdown
上半部分。

---

下半部分。
```

分隔线前后留空行，避免与标题语法混淆。练习时复制示例并比较有空行和无空行时的显示结果。

## 标题层级的选择

把一篇文档当成一本小手册，一级标题说明整篇讲什么，二级标题回答读者主要问题，三级标题说明某一步内部的细节。不要为缩小字号跳过层级，也不要把每句话都设成标题。标题是结构，字体大小由主题控制。主题变更后结构仍应成立，读者才能通过目录定位。

## 连续文字为什么没有换行

Markdown 中一段连续文字可以在源码里分成几行，排版时仍属于同一段。这让编辑时控制行长，不必让读者看到很多断行。如果两个步骤必须分开，优先使用列表或分段。确需同段换行时使用明确语法，不能依赖不同平台对单次回车的处理一致。

## 空行的作用

标题、列表、引用与代码块前后留空行，能减少不同结构相互吞并。写完一个代码块后先闭合围栏，再空一行开始下一段。不要用连续很多空行模拟页面高度，预览通常会合并空白，窄屏显示也不会保持你在编辑器中看到的位置。

## 分隔线与标题下划线

短横线紧接上一行文字时会参与另一种标题写法，分隔线前保留空行才能明确表达分隔目的。维护手册时统一使用井号标题，更容易在源码中辨认层级。示例中的短横线属于语法，不是正文中的连接标点。

## 实际练习

写一页“部署检查”，下面设置“准备”“执行”“验证”三个二级标题，再在验证下设置“首页”和“登录”两个三级标题。每节至少一段文字。保存后检查目录顺序，再把第一段故意改为单次回车，比较它与空行分段的差异。修正后重新打开确认结果。
