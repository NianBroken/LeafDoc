# 表格与对齐

## 基本表格

```markdown
| 项目 | 状态 | 说明 |
| --- | :---: | ---: |
| 网关 | 正常 | 可访问 |
| 应用 | 正常 | 健康检查通过 |
```

首行为表头，第二行为分隔行，后续为数据。冒号放在左边表示左对齐，两边表示居中，右边表示右对齐。

| 项目 | 状态 | 说明 |
| --- | :---: | ---: |
| 网关 | 正常 | 可访问 |
| 应用 | 正常 | 健康检查通过 |

## 单元格内容

单元格可包含强调、行内代码和链接。竖线需要写成 `\|`，否则会被识别为列分隔符。长命令和多段操作不要塞进单元格，应另建代码块。

## 练习与排错

建立三列表格记录文件、用途、是否需要修改。表格没有出现时检查分隔行是否存在，列数是否相同，以及表格前是否留有空行。

## 让每列有明确含义

表头应写真实属性，例如名称、作用、填写要求、默认行为，而不是信息一、信息二。每行是一个可查询对象，路径相同才允许合并说明。同名字段出现在不同层级时分别列出完整路径，避免读者改错位置。

## 默认值和示例值不同

表格中出现一个值，不等于程序缺省就使用该值。配置手册要区分文件当前值、脚本生成值、未填写行为和示例。没有默认值就明确写没有，不能为了表格整齐填上虚构内容。必填字段还应说明填写来源和格式。

## 宽表和窄屏

项目为表格提供横向滚动，但过多长段落仍难阅读。将字段事实放在表里，将连续操作放在表外代码块。空单元格使用明确的“不适用”说明，避免读者把空白误认为未知。对齐只影响显示，不改变数据类型。

## 特殊字符

单元格需要显示竖线时用转义，代码中的竖线也应检查是否把列切开。表格行不能直接拆成多个源码行表示同一行长文字。多段说明改为独立小节，再从单元格链接过去，但该单元格仍应保留基本用途。

## 检查练习

建立名称、填写要求、未填写行为三列表格，记录三个真实配置项。逐行确认三列都有具体内容，再加入一个含竖线的示例并检查列数。缩小浏览器窗口，确认表格能滚动，复制单元格不会带入额外分隔符。
