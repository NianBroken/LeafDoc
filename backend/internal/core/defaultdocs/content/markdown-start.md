# Markdown 入门与编辑实践

## 从输入到保存

Markdown 用普通文本表达结构。在编辑区输入标题、列表或代码，预览区将这些符号转换为可阅读的版式。正文格式和左侧页面树是两件事，输入 `##` 不会创建子页面。

1. 在左侧选择教程，再进入编辑模式。
2. 将下面示例复制到自己的练习页面。
3. 检查预览，保存后重新打开页面确认正文。

```markdown
# 值班记录

今天完成了 **数据库连接检查**。

- 检查服务状态
- 查看访问日志
```

预览应出现一个标题、一段带加粗文字的说明和两个列表项。保存成功后，刷新仍能看到内容。没有编辑权限时只能阅读，应由管理员分配编辑者角色。

## 页面与章节

章节可以包含正文和子页面，普通页面不包含子节点。本教程有三个一级章节，展开左侧章节能看到七篇二级页面。页面移动和正文标题变化互不替代。

## 实践

建立一篇“今日记录”，用标题描述日期，用列表记录实际操作。不要把整篇正文放入代码围栏，否则预览只会显示源码。

## 阅读与编辑的实际区别

阅读模式展示格式处理后的内容，编辑模式展示产生这些效果的文字。不要把预览中看到的加粗文字直接当作源代码，复制教程的代码块才能保留符号。保存前检查页面标题和正文，标题字段用于侧栏显示，正文开头的一级标题用于阅读，它们分别维护。只改正文标题不会自动修改树中的名称。

## 从空白页完成一次写作

为练习页面起一个明确名称，例如“开发环境检查”，路径选择容易辨认的短名称。正文先写本页用途，再写三个步骤，每个步骤都加一条观察结果。用预览确认列表没有混进代码块。保存后离开本页，再从侧栏进入，检查文字与格式仍在。这个过程同时验证了输入、显示和持久保存，单看编辑器里的文字不能确认已经写入服务器。

## 保留可复制信息

命令、文件名、字段名用反引号，完整操作用代码块。说明文字放在代码块外，不把“请执行下面命令”复制给终端。需要读者自己填写的内容写清来源，避免给出看似可用的假密码。示例命令只描述写法，不在页面中自动执行，实际操作由读者在对应环境完成。

## 保存与协作检查

多人编辑同一页时，不要连续覆盖提交。遇到版本冲突，重新读取服务器正文，对照自己的修改后再保存。浏览器页面关闭并不等于保存完成，先确认成功反馈。没有权限的用户应联系管理员配置角色，复制链接不能提高编辑权限。

## 完成标准

练习页应能重新打开，侧栏名称准确，正文有一个主题标题，步骤顺序清楚，每个命令有解释，每个结果能观察。再让另一位有读取权限的用户打开链接，确认页面用于实际交流，而不是只在作者浏览器内可见。
