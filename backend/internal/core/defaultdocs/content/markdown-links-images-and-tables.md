# 链接、图片与表格

链接提供到其他资料的入口，图片展示难以用文字描述的细节，表格方便比较同类信息。三者都需要准确的目标和完整的上下文。页面显示出蓝色链接并不代表目标有效，保存后必须实际打开检查。

## 行内链接

方括号中写显示文字，紧接的圆括号中写网页地址。文字应说明目标内容，避免一页中出现多个无法辨认的“点击这里”。

```markdown
[阅读写作流程](/markdown-getting-started)
[查看 CommonMark 规范](https://spec.commonmark.org/)
```

实际入口：[阅读写作流程](/markdown-getting-started)与[查看 CommonMark 规范](https://spec.commonmark.org/)。内部链接使用页面地址，外部链接使用完整的 HTTPS 地址。不能把 Windows 文件路径当成网站地址。

## 文档之间相互引用

这套教程使用稳定的页面地址。例如需要了解列表时，引用[列表、引用与内容组织](/markdown-lists-and-structure)。修改文章标题时应检查地址是否同时变化；若地址变化，应同步检查其他页面里的引用。系统的链接检查功能可用于发现遗漏，但仍需要实际点击关键入口。

## 引用式链接

同一个网址出现多次时，可以集中写一条引用定义，正文通过名称使用。引用名称只是源码中的标识，阅读页面显示的是链接文字。

```markdown
[通用语法][commonmark]

[commonmark]: https://spec.commonmark.org/
```

这种方式适合多次引用规范或项目主页的长文章。定义名称必须与使用处一致，避免写了定义却用另一个名称。不要把定义写进代码块后期待正文自动识别。

## 同页标题定位

标题可以生成页内定位地址。英文标题通常以小写单词和短横线组成地址，中文和特殊标点的处理应以系统生成的标题链接为准。最可靠的操作是从实际标题复制链接，再保存到正文，不能只凭标题文字猜测锚点。

本篇提供一个明确的英文标题作为练习目标。

### link-check

[跳转到链接检查位置](#link-check)。点击后应定位到本节。重复标题会产生不同的定位后缀，因此需要固定引用的小节应使用唯一标题。

## 图片语法

图片在链接语法前增加感叹号。方括号内容是替代说明，用于图片无法显示时说明内容，也帮助读屏工具理解图片。说明应描述图中关键内容，而不是只写“图片”。

```markdown
![LeafDoc 默认标志](/defaults/leafdoc-logo.webp)
```

实际图片：

![LeafDoc 默认标志](/defaults/leafdoc-logo.webp)

该资源由项目内置提供，不依赖外部图片网站。业务附件应先通过系统上传，再使用返回的实际地址。不要引用聊天临时地址、本机桌面目录或会过期的下载地址。

## 图片尺寸与清晰度

Markdown 图片默认保持自身比例，页面会根据可用空间显示。横图和竖图的留白不同，不能通过拉伸让所有图片变成一样的外形。大图应确保文字仍然清楚，操作截图需要裁到相关区域，避免读者在整张桌面中寻找按钮。

## 基本表格

竖线分隔列，第二行用短横线声明表头分隔。每行的列数保持一致。单元格尽量写短句，长段落放在表格外面。

```markdown
| 项目 | 写法 | 用途 |
| --- | --- | --- |
| 标题 | 井号加空格 | 组织层级 |
| 代码 | 反引号 | 保留原文 |
| 列表 | 短横线加空格 | 罗列事项 |
```

显示结果：

| 项目 | 写法 | 用途 |
| --- | --- | --- |
| 标题 | 井号加空格 | 组织层级 |
| 代码 | 反引号 | 保留原文 |
| 列表 | 短横线加空格 | 罗列事项 |

## 表格对齐和特殊字符

分隔行左侧冒号表示左对齐，两侧冒号表示居中，右侧冒号表示右对齐。单元格内需要竖线时使用反斜杠转义，避免它被当成下一列。

```markdown
| 名称 | 状态 | 数量 |
| :--- | :---: | ---: |
| 示例 A | 完成 | 12 |
| 示例 B | 待处理 | 3 |
```

对齐声明属于 Markdown 语义，站点的公共表格样式还会统一行高、边距及窄屏显示。验收时看实际页面，不用源码里的空格模拟列宽。

## 保存前逐项检查

点击所有内部链接，确认进入对应文档；点击页内链接，确认落在正确标题；打开图片原地址，确认资源存在；打开外链，确认目标页面可访问且内容与引用文字一致。出现错误时直接修正地址或替换引用，不保留失效入口。

表格扩展的正式规则见 [GFM 规范](https://github.github.com/gfm/)。
