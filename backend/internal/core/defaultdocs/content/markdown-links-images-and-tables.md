# 链接、图片与表格

## 指向页面与外部资料

标准链接由显示文字和目标地址组成。目标必须是实际存在的页面或资源。

```markdown
[入门教程](/markdown-getting-started)
[CommonMark 规范](https://spec.commonmark.org/)
```

站内地址应使用实例当前路径规则。在带基础路径的实例中，检查实际点击结果，不要把另一个实例的完整地址照搬过来。页面移动后也应检查入链，而不是只检查新页面能否打开。

## 图片和附件

上传资源后使用系统返回的地址。下面使用程序自带图片，预览中应出现 LeafDoc 图标。

![LeafDoc 标志](/defaults/leafdoc-logo.webp)

![LeafDoc 图标](/defaults/leafdoc-icon-180.png)

```markdown
![图片说明](/defaults/leafdoc-icon-180.png)
```

图片说明用于表达图片含义。需要下载的文件使用普通链接。不要把本机磁盘路径写成其他读者的附件地址。文件是否可读仍受到实例访问设置和接口权限约束。

## 表格

```markdown
| 检查项 | 结果 |
| --- | --- |
| 首页 | 可以打开 |
| 登录 | 进入文档树 |
```

表格适合比较并列信息，长篇操作步骤应写成列表。单元格包含竖线时需要转义，否则会形成新的列。列数不同导致显示错位时，先检查分隔行和每一行的竖线。

## 实际检查表

| 检查对象 | 操作 | 预期结果 |
| --- | --- | --- |
| 页面 | 重新打开 | 正文存在 |
| 图片 | 阅读预览 | 图像清晰 |
| 附件 | 打开下载 | 文件完整 |

### link-check

这是链接检查示例的固定标题。预览为标题生成站内定位点，其他段落可使用 [返回链接检查](#link-check) 跳转。用标题生成的定位点时，应在标题修改后重新核对相关链接。

## 链接验证

保存后逐个点击重要链接。图片未显示时核对资源是否上传、地址是否正确、当前账号是否具有读取权限。

## 为链接提供可辨认的目标

链接文字应说明目标是什么，例如登录检查记录、附件列表或语法规范，不能把整篇文章里的所有链接都写成点击这里。读者在点击之前就应知道将要打开文档、下载文件还是离开当前网站。站内链接在页面重命名或移动后需要重新验证，不能只确认导航树中的新名称正确。访问带前缀的实例时，检查点击后的地址是否仍位于本实例中，避免误入另一个部署环境。

链接校验应覆盖真实读者使用的账号。管理员能看到的页面，不代表普通读者也有相同权限。遇到访问被拒绝时，应核对目标页面权限与账号身份，不能通过把私有资料复制到公开页面来绕过限制。外部资料引用应保留足以辨认来源的名称，正文说明引用内容解决的具体问题。不要把会过期的临时下载地址当作长期文档依据。

## 让图片在不同设备上仍可理解

图片必须附带能说明内容的替代文字。截图中包含多个按钮时，在正文中写出操作对象和顺序，不要只依靠颜色或鼠标位置表达含义。手机屏幕较窄，整屏截图中的小字难以辨认，应将说明集中到真正需要观看的区域。图片展示配置时，先遮去密码、密钥、个人信息和内部地址等不应公开的内容，再上传到文档系统。

不要把本机盘符、浏览器缓存路径或临时文件夹地址写成图片链接。这些位置只能在作者设备上访问，其他读者无法获取。上传后使用系统返回的资源地址，并在阅读界面重新打开。图片失效时核对文件是否仍存在、链接是否完整以及权限是否允许读取。替换图片时保留正文解释与实际画面的一致性，不能只换文件却继续引用旧按钮名称。

## 用表格比较信息而非隐藏步骤

表格中的每一列应具有稳定含义，每一行应描述同一类对象。比较检查项时可以使用检查对象、动作与结果三列，避免把整篇操作说明塞入单个单元格。长文本会使窄屏阅读困难，复杂步骤应放回普通段落或编号列表。数字和状态应采用统一写法，使读者能够直接比较，不能在同一列里混用含义不明的缩写。

编写表格后检查表头分隔行和每行列数。内容中的竖线需要转义，代码示例包含竖线时也要检查最终预览。表格只是呈现文字，不会像电子表格一样自动计算，也不会在后台执行检查。完成文章后逐项打开链接、读取附件并核对图片，再保存与重新打开。这样能够发现只有作者设备能访问的资源，以及只有编辑界面正常、阅读界面失效的问题。
