# Markdown 内容组织

## 用结构表达顺序

操作说明应先写目的，再列步骤，随后给出成功结果。无序列表表达并列事项，有序列表表达执行次序，引用块提示限制，代码块提供可复制内容。

````markdown
## 检查服务

运行以下命令查看容器：

```sh
docker ps
```

看到目标容器处于 Up 状态后，再检查健康接口。
````

复制嵌套围栏示例时，外层需要使用四个反引号，里面的三反引号才能作为文本展示。

## 真实页面层级

在左侧展开本章节，可阅读列表、引用代码和表格教程。正文的小标题只控制阅读结构，创建二级页面需要通过页面树操作。

## 练习

把一段连续说明拆成“目的”“操作”“结果”三个二级标题。用列表列出检查点，用代码块表示命令，确认各块之间留有空行。

## 让读者知道从哪里开始

操作页开头写出适用环境和目标状态，紧接着说明准备条件。不要先放十条没有解释的命令，再在末尾告知它们只能在服务器运行。读者应在执行前就知道当前机器、目录、权限和所需文件。命令完成后写能看见的成功结果，例如健康接口返回、页面能打开或登录成功。

## 一个页面只承担清楚的主题

短说明不需要拆成很多页面，复杂步骤也不应挤进一张超宽表格。把完整路径放在一个主题页里，子页面解释独立细节。父章节的正文可以提供阅读顺序，子页面提供实际操作。页面树用于内容组织，正文标题用于页内定位，两者共同帮助读者，但不能互相替代。

## 选择列表还是表格

需要按顺序执行就用有序列表，需要比较几项属性就用表格，需要并列检查项就用无序列表。把长命令放在代码块，表格里只写名称和简短作用。为了压缩篇幅把全部操作塞进单元格，会使复制和手机阅读都变得困难。

## 引用与警示的边界

引用块用于突出限制和背景，不让它承载所有主步骤。读者应能沿正文顺序完成任务，不必在很多提示框之间拼接操作。限制要写清实际后果，例如主动停止后重启策略不会自动拉起，而不是只写一句“注意保活”。

## 练习结果

将一段没有格式的操作记录整理成用途、准备、步骤、检查和故障五部分。每部分回答一个明确问题。让读者按顺序执行时不用回头寻找参数。检查标题是否清楚、步骤是否连贯、成功条件是否可观察，再保存并重新阅读。
