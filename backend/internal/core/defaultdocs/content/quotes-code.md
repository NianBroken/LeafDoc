# 引用与代码块

## 引用

```markdown
> 执行更新前，确认新压缩包校验通过。
>
> 不要删除持久化数据。
```

每行前的 `>` 将文字显示为引用。多段引用之间的空行也加 `>`，才能保持同一引用区域。

## 代码块

代码围栏使用三反引号起止，起始行可写 `sh`、`json` 等语言名称。语言名称控制高亮，不会执行命令。

```sh
docker ps
```

```json
{"status":"ok"}
```

代码块中的命令不会自动运行。复制命令前确认所在机器、目录和权限，不要把说明文字一起交给终端。

## 围栏本身的写法

外层四反引号可以展示内部三反引号。围栏未闭合时，后面所有文字都会成为代码。练习写一个 shell 示例，故意移除结束围栏，观察结果后恢复。

## 解释命令执行位置

在代码块前说明命令在哪台机器执行，是否需要 root，当前目录是什么。Docker 宿主和容器内部路径不是同一位置，文档中必须分清。代码高亮只识别语言，不检查文件是否存在或权限是否充分。执行前仍需确认参数和数据范围。

## 输入和输出分开

供复制的代码块只放输入命令，预期输出另起一块或用文字说明。不要把终端提示符当成命令的一部分，尤其是美元符号和井号会被初学者一并复制。输出会随机器变化时描述关键状态，不要求读者得到相同容器 ID 或时间戳。

## 展示 Markdown 源码

教程需要把三反引号本身显示给读者时，外层使用更多反引号。内外围栏长度相同会提前结束外层，后面文字被当成正文。检查结束围栏是否独立成行，语言名只放在开头，不放在结尾。

## 引用的实际用途

引用可以保存别人的原话，也可以突出操作限制。内容是引用不表示它已经验证，实际项目行为仍由代码和运行结果确认。引用多段文字时保留引用标记，避免下一段意外回到普通正文。

## 练习验收

建立一个说明 docker ps 的例子。块前写“在 Ubuntu 宿主执行”，块内只放命令，块后说明 Up 状态代表容器主进程运行，仍需检查应用访问。再用引用说明不要删除数据卷。复制命令后检查没有提示符和说明文字。
