# 列表与任务清单

## 无序列表

```markdown
- 应用服务
- 网关服务
- 外部数据库
```

短横线后留一个空格，每项单独一行。并列项不应暗示执行顺序。

## 有序列表

```markdown
1. 准备配置
2. 启动服务
3. 检查访问
```

预览显示编号，适用于不可交换顺序的操作。需要在某一项内写多段内容时，应缩进到该项正文起始位置。

## 嵌套与任务

```markdown
- 部署检查
  - 端口可访问
  - 配置已保存

- [x] 已完成启动
- [ ] 尚未验证登录
```

- [x] 已完成启动
- [ ] 尚未验证登录

任务标记由方括号、空格或小写 x 组成。这里表达正文状态，不能代替项目服务的真实健康检查。修改复选状态后仍需保存正文。

## 排错与练习

子列表跑到根层级时检查缩进，普通段落变成代码时检查多余的四空格缩进。练习写出两层检查清单，再添加已完成和未完成各一项。

## 列表不是手工排版工具

列表表示一组有关系的项目，不用空格强行把内容推到屏幕右边。不同字体和屏幕宽度会改变空格显示，结构化列表仍能保持顺序。每个项目尽量以实际动作或明确对象开头，不让一条列表同时承担多个不相关主题。

## 多行内容留在同一项

某一步需要解释原因或展示代码时，将续行缩进到该项正文位置。续行未缩进就会脱离列表，缩进过多又会变成代码。编辑时对照预览，确认代码属于正确步骤。子项不能替代下一步编号，只有必须先后执行的动作才使用数字序列。

## 勾选表达的是文档状态

任务清单里的勾选是作者记录的状态，不是后端检测结果。写“已检查登录”应真的完成一次登录，否则清单会误导维护者。涉及多个环境时在项目中写明环境名称，避免一个勾选被理解成所有服务器都已通过。

## 避免混用标记

同一层统一使用一种无序标记，能让源码更容易扫读。不要在数字后缺少空格，也不要把中文序号当成标准有序列表语法。需要原样展示编号时放到代码块，避免渲染器重新编号产生误解。

## 完整练习

写出准备配置、启动服务、确认访问三个步骤。给准备配置加两条子项，在确认访问下写健康与登录两个任务框。先只勾健康检查，完成真实登录后再勾登录。保存后重新打开，确认层级、顺序、状态与操作事实一致。
