# fnOS Docker 纯可视化部署

适用对象为 x64 fnOS，验收目标版本为 1.2.0800。软件仍是 Docker 应用，原有 Ubuntu 系统安装方式继续保留。部署所需镜像已经包含在发行包中，不要求 NAS 下载镜像或编译源码。数据库使用外部 MySQL，需事先创建数据库并提供建表与读写权限。

## 上传与导入

在电脑解压完整发行归档。在 fnOS 文件管理的“我的文件”建立 LeafDoc 部署资料目录，上传 images.tar。在电脑的可视化文本编辑器打开 fnos/docker-compose.yml，将顶部 LEAFDOC_HOSTS 的空字符串填写为 NAS 的实际 IP 或主机名，多个地址用空格分隔。不要填写浏览器协议、端口或路径。将编辑后的文件也上传到 NAS 以备维护。

打开 Docker 的“本地镜像”，点击“添加镜像”，选择“从 NAS 文件添加”，选中 images.tar 并确认。等待发行应用镜像和 Caddy 镜像显示完成。完整发行 tar.gz 不是镜像归档，不要把它直接送入镜像导入窗口。

## 创建与启动

打开“Compose”，点击“新增项目”，填写固定项目名称，例如 leafdoc。选择专用部署目录，来源选“上传docker-compose.yml”，选择电脑上已经填写访问地址的 fnOS 专用文件。勾选“创建项目后立即启动”并确认。项目第一次启动会创建自己的持久卷，prepare 服务自动生成令牌、权限、证书和网关配置。prepare 正常退出且退出码为零表示准备完成，不应把它当作需要持续运行的业务容器。

在容器或项目详情中打开 prepare，点击“更多 → 运行日志”，读取首次安装令牌。该令牌只在初始化未完成时输出，不要把截图或日志公开。应用和网关依赖准备成功，失败应根据日志修正顶部配置再更新项目，不能跳过准备服务。fnOS 将包含已退出 prepare 的项目显示为“部分运行”，这是一次性服务的正常显示。应分别确认 prepare 退出码为零、app 与 gateway 为运行中，而不是要求三个服务持续运行。

默认 HTTPS 入口为 https://NAS地址:24691。公开 CA 的下载入口为 http://NAS地址:24690/api/setup/ca，明文端口只接受公开证书下载，其他请求返回拒绝。先下载 CA 并在访问设备信任，再打开 HTTPS 引导页，不要通过关闭证书校验或忽略安全警告继续。CA 经明文传输，应在可信局域网获取，并用 prepare 日志中的 SHA256 指纹核对。系统完成初始化后下载接口关闭，已下载的公开证书应妥善保留。

在引导页填写令牌、外部 MySQL 地址、端口、数据库、账号、密码以及管理员资料。TLS 数据库支持自定义 CA，证书必须与数据库主机名匹配。提交会真实准备表结构和验证读写，成功保存后才进入正式系统。重启、重建与升级不重新要求初始化。

## 配置与维护

默认只发布 HTTPS 和公开证书下载两个端口，不占用 fnOS 的 80 与 443。修改左侧宿主映射端口后使用对应端口访问，右侧容器端口保持原值。路径前缀填入顶部 LEAFDOC_BASE_PATH，并在访问 URL 与 CA 下载 URL 前加上该路径。首次证书包含填写的全部地址。后续更换地址时，在项目的 YAML配置页更新顶部参数并重新构建项目，prepare 会比较参数摘要，使用原 CA 重新签发服务器证书，不删除配置卷。服务器证书距到期不足三十天时，下一次执行 prepare 也会重新签发。正常长期运行应安排在到期前通过界面重建一次项目。

公网部署填写顶部 LEAFDOC_DOMAIN，清空 LEAFDOC_HOSTS，并把网关端口映射配置为宿主 80 到容器 80、宿主 443 到容器 443。保留原 HTTPS 映射不影响其他站点配置，但公网域名入口使用标准 443。公网模式使用 Caddy 自动证书，需要正确域名解析和挑战入口。fnOS 或其他服务占用这些端口时，应通过既有前置代理转发，不能强行占用其管理端口。公网模式没有本地 CA 下载流程。

升级时导入新发行包的 images.tar，在原 Compose 项目点击“停止”，然后打开“YAML配置”更新专用 YAML。运行状态下该页只读，停止后才能编辑，编辑结果由界面自动保存。使用“更多 → 构建”使配置生效，保留项目名称、访问参数和全部卷。新 YAML 中应用镜像标签来自同一次构建，prepare 和 app 必须同时更新，禁止只复制其中一个旧标签。无需手动执行 docker 命令，也不需要打开容器终端。

停止与启动在 Compose 项目操作中完成，日志在项目或容器详情查看。普通卸载保留卷，彻底重装才明确删除该项目的数据卷。数据库是独立资源，不会随项目删除。备份需同时覆盖应用数据、配置和公开证书卷及外部 MySQL；应用快照不能替代实例证书与连接配置备份。

prepare 只有项目卷权限，不使用特权模式、宿主系统路径或 Docker 套接字。业务进程使用专用低权限用户。公开证书独立只读挂载，应用无法通过该挂载读取 CA 私钥。不得把这些限制删除以绕过权限问题。

## 核验要求

实际验收应从空项目开始，通过文件管理上传、镜像导入、Compose 创建、首次引导和业务操作走完整流程。需要记录镜像标签、归档 SHA256、fnOS 版本和界面截图。仅看到 Running 不等于数据库与全部功能可用。错误令牌、错误数据库、准备失败和证书错误必须被拒绝。未实测的宿主、外部集成和公网证书签发应单独说明。
